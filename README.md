# Проект Online_store_django

## Описание:
Проект Online_store_django — это веб-приложение интернет-магазина (каталога товаров), созданное на основе фреймворка Django. Реализован вывод товаров с динамическим усечением текста, детальные карточки продуктов с поддержкой изображений, а также форма добавления новых товаров с возможностью динамического выбора категорий из базы данных.

## Установка и запуск проекта:

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/KlimanovGrigoriy888/Online_store_django.git
   cd Online_store_django
   ```

2. **Создайте виртуальное окружение:**
   ```bash
   python -m venv venv
   ```

3. **Активируйте виртуальное окружение:**
   * Для Windows:
     ```bash
     venv\Scripts\activate
     ```
   * Для macOS/Linux:
     ```bash
     source venv/bin/activate
     ```

4. **Установите необходимые зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

5. **Настройте базу данных PostgreSQL:**
   Выгрузите и установите PostgreSQL с [официального сайта](https://www.postgresql.org/download/windows/). С помощью утилиты pgAdmin или консоли создайте базу данных и пользователя:
   ```sql
   CREATE DATABASE <название_вашей_базы_данных>;
   CREATE USER <имя_пользователя> WITH PASSWORD '<ваш_пароль>';
   ALTER DATABASE <название_вашей_базы_данных> OWNER TO <имя_пользователя>;
   ```

6. **Настройте переменные окружения:**
   Внесите ваши данные подключения к БД (`DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`, `DATABASE_HOST=localhost`, `DATABASE_PORT=5432`) в файл `.env.sample` и переименуйте его в `.env`.

7. **Примените миграции базы данных:**
   ```bash
   python manage.py migrate
   ```

8. **Запустите сервер разработки:**
   ```bash
   python manage.py runserver
   ```
   Сайт будет доступен в браузере по адресу: `http://127.0.0`

## Полезные команды при разработке:
* Проверить список установленных пакетов: `pip list`
* Сохранить новые установленные пакеты в зависимости: `pip freeze > requirements.txt`

## Архитектура и функционал проекта:

1. **Запуск и страницы:**
   * Проект представляет собой веб-сервер интернет-магазина, который обрабатывает и рендерит страницы каталога (`products_list.html`), контактов (`contacts.html`), показа деталей товара (`product_detail.html`), формы добавления и изменения продуктов (`product_form.html`) и форму удаления продукта (`product_confirm_delete.html`).
   * Добавлено приложение 'blog', для создания, изменения, просмотра записей блогов и рендерит страницы каталога (`products_list.html`), контактов (`contacts.html`), показа деталей блога (`blog_detail.html`), формы добавления и изменения блога (`blog_form.html`) и форму удаления продукта (`blog_confirm_delete.html`).
   * Добавлено приложение 'user' с кастомной моделью пользователя `CustomUser` с авторизацией по Email и с проверкой токена по электронной почте регистрирующегося пользователя. Созданы html формы для регистрации пользователя (`register.html`), и входа пользователя (`ligin.html`).
   **Интерфейс шаблонов:** 
   * Кнопки действий (Редактировать/Удалить) динамически скрываются или отображаются с помощью тегов `{% if perms ... %}` и проверок владельца.
   
2. **Права доступа в Каталоге:**
   * Обычный пользователь (владелец) может редактировать только свои продукты через `ProductUserForm` (без изменения статуса публикации).
   * Создана группа «Модератор продуктов». Модератор может редактировать статус публикации любого товара через `ProductModeratorForm` (контент при этом защищен от изменений) и удалять любые продукты.
   * Посторонним пользователям доступ к редактированию и удалению жестко закрыт на уровне сервера (ошибка 403 Forbidden через метод `dispatch`).
   **Права доступа в Блоге (Дополнительное задание):**
   * Создана кастомная команда для автоматического создания группы «Контент-менеджер».
   * Доступ к созданию, редактированию и удалению статей блога защищен с помощью `PermissionRequiredMixin` и системных прав (`blog.add_blogentry`, `blog.change_blogentry`, `blog.delete_blogentry`).
   
3. **Принцип наследования шаблонов:**
   * Реализован принцип наследования шаблонов: создан базовый шаблон `base.html`, содержащий общую структуру сайта (метатеги, подключение стилей Bootstrap и скриптов JavaScript).
   * Изолирован повторяющийся компонент шапки сайта в отдельный файл `header.html`, который динамически подключается во все дочерние шаблоны через тег `{% include %}`.
   * Страницы каталога, контактов и форм расширяют базовый шаблон с помощью тега `{% extends %}`, что обеспечивает строгую структурированность кода и исключает дублирование верстки.
   
4.**Контроллеры (`catalog/views.py`):**
   * Реализованы контроллеры на базе CVB базируемые на классах и наследуемые от класса View, реализующие CRUD операции.
   * В контроллер главной страницы добавлен код, выводящий в консоль выборку из 5 последних созданных продуктов при каждом её вызове с помошью метода get_queryset(self).
   * В контроллер главной страницы добавлен метод def post(self), этот метод перехватывает POST-запрос от формы ввода ID с базового шаблона и делаем редирект на страницу деталей по запрашиваемому product_id в форме, ищет через адрес и pk через адрес указанный в urls.py адрес 'product/<int:pk>/'
   * Настроена обработка POST-запросов: получение данных формы обратной связи на странице контактов, быстрый поиск товара по ID на главной странице, а также создание новых продуктов с поддержкой загрузки файлов через базовые классы ViewDetail, ViewCreate, ViewUpdate.

   **Контроллеры (`blog/views.py`):**
   * Реализованы контроллеры на базе CVB базируемые на классах и наследуемые от класса View, реализующие CRUD операции.
   * В контроллер страницы детальной информации о блоговой записи BlogDetailView().
     В нем добавлен код, производящий подсчет просмотров детальной информации конкретной блоговой записи.
     Подсчет просмотров реализован с помощью метода получения данных из базы данных get_object(queryset) и изменения данных параметра счетчика object.views_count на 1 при просмотре вызове страницы 'blog/blog_detail.html'.
     Так же добавлен код производящий отправку себе на почту поздравление с достижением о 100 просмотров.

   **Контроллеры (`user/views.py`):**
   * Реализован контроллер на базе CVB базируемый на классе и наследуемый от класса CreateView, реализующие операцию регистрацию пользователя.
   * В conf/settings.py указываем кастомную модель пользователя AUTH_USER_MODEL = 'users.CustomUser'
   * В контроллер страницы регистрации пользователя добавлена функция form_valid().
     В ней осуществляется генерация и отправка токена для валидации пользователя по электронной почте.
   * В контроллер страницы регистрации пользователя добавлена функция email_verification().
     В ней осуществляется верификация токена от почты пользователя и его сравнения с сохраненным в БД и отправка ответного письма об успешной верификации
   * В контроллер страницы регистрации пользователя добавлена функция send_welcome_email().

     Функция отправляет письмо зарегистрированному пользователю о его успешной регистрации используется в функции верификации email_verification()
5.**Реализован механизм CRUD для модели продуктов, используя модуль django.forms. В модуле forms.py приложения catalog реализована модель ProductForm и в нем созданы методы:**
   * Метода clean. В нем реализована валидация на запретные слова в полях 'name' 'purchase_price'.
   * Метод clean_purchase_price. В нем реализована валидация для поля 'price' на проверку цены продукта, что она не может быть отрицательной.
   * Метод clean_picture. В нем реализована валидация для поля 'price', проверка на формат и размер загружаемого файла, чтобы загружаемые файлы имели формат JPEG или PNG и не превышали размер 5 МБ.
   * Метод __init__ выполнена настройка атрибутов виджета стилизации форм для полей 'name', 'purchase_price', 'description', 'category', 'picture'

10. **Работа с фикстурами:**
   * Создан файл фикстуры `products_fixture.json` в корне проекта.
   * Для выгрузки данных из БД в файл (с поддержкой кодировки UTF-8) используется команда:
     ```bash
     python -Xutf8 manage.py dumpdata catalog.Product catalog.Category --output products_fixture.json --indent 4
     ```
   * Для обратной загрузки данных из фикстуры в чистую базу данных используется команда:
     ```bash
     python manage.py loaddata products_fixture.json
     ```

11.**Кастомные команды управления (Management Commands):**
   В пакете `catalog/management/commands/` созданы два python-модуля для автоматизации:
   * `add_product` — команда, которая программно заполняет базу данных новыми тестовыми объектами классов `Product` и `Category`.
   * `load_fixture` — команда, которая автоматически наполняет базу данных из файла фикстуры `products_fixture.json` с помощью встроенной функции Django `call_command`.
   В пакете `users/management/commands/` созданы три python-модуля для автоматизации:
     * `csu` — команда, которая программно создает пользователя с правами администратора с email="admin@example.com" и паролем "123qwe".
     * `dcu` — команда, которая автоматически удаляет всех пользователей исключая пользователя с правами администратора.
     * `cmg` - команда, которая программно создает группу пользователей 'Модератор продуктов' с правами изменения статуса публикации и удаления продукта
     * `skmg` - команда для создания группы 'Контент-менеджер' с правами изменения публикациями в блоке
     
       Вызов кастомных команд осуществляется через терминал:
       ```bash
       python manage.py add_product
       python manage.py load_fixture
       ```
